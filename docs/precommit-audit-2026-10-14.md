# Предкоммитная проверка materials — 14.10.2026

Проверена вся незакоммиченная серия относительно `0591892`: сохранение workspace, `ssr: false`, сортировка «Общих данных», «Все / Заполненные», фиксированный порт, инструкции/контекст и добавленные в ходе проверки исправления. Пользователь запросил проверку и push; коммит и отправка относятся к этому запросу. Это не deploy и не отдельный аудит всей будущей архитектуры.

## Исправленные проблемы

- Ошибки чтения/JSON snapshot больше не превращаются в пустое состояние. Отсутствующий файл различается с повреждением или ошибкой доступа; при ошибке загрузки файл не перезаписывается.
- Вместо прямой записи в рабочий JSON используется временный файл и атомарный rename. Сервер сравнивает ревизию, последовательно обрабатывает записи и отклоняет устаревшие изменения; повтор запроса с уже сохранённым содержимым идемпотентен.
- Серверный snapshot имеет приоритет над отличающимся устаревшим браузерным кэшем. Локальная копия сохраняется для восстановления; незавершённые offline-изменения восстанавливаются автоматически только при совпадении базовой серверной ревизии. Ответ одной вкладки не уничтожает несохранённую копию другой.
- На обычном открытии страницы запись не выполняется. Клиент допускает один незавершённый save, объединяет промежуточные изменения, показывает ошибки/конфликты и позволяет скачать текущие данные. Ошибка localStorage не блокирует серверное сохранение.
- Удалён опасный URL-сброс `?reset=1`. Путь snapshot больше не зависит от размещения скомпилированного модуля: корень запуска проекта либо явно заданная тестовая папка. GET snapshot помечен `Cache-Control: no-store`.
- Устранены лишние refetch неизменяемого плана на mount/focus/reconnect. Сохраняемые необязательные поля нормализуются в JSON, чтобы `undefined` не ломал создание заявки.
- Включён `noUncheckedIndexedAccess`: типы больше не объявляют каждый элемент массива/словаря существующим. Добавлены проверки отсутствующего листа Excel/проекта, безопасные значения для пустых ячеек, исправлены оставшиеся замечания линтера. Правила ESLint не отключались.
- Сортировка одинаковой даты сохраняет последнюю вставленную запись выше более старой внутри каждого типа операций. Фильтр «Заполненные» использует конечное число > 0, включая десятичную запятую. Добавлены регрессии и проверка сохранности цветов.

## Ограничения и следующие темы

- PostgreSQL integration skipped: `DATABASE_URL_TEST` не задан. БД, Docker и миграции не запускались; функциональных изменений схемы/SQL в серии нет.
- Текущий интерфейс хранит один workspace в файле и localStorage. Нет полной многопользовательской модели/авторизации для публичного хостинга. Оптимистическая версия защищает вкладки одного локального сервера; несколько независимых серверных процессов с одной папкой не поддерживаются.
- Сохранение/валидация/сериализация остаются пропорциональными размеру всего snapshot. Большой согласованный набор materials для нагрузочного теста пока не определён. Проверены число RPC и логика очереди; SQL-нагрузка к текущему файловому пути не относится.
- Исторические записи имеют дату документа и порядок в массивах, без общего времени изменения. Между разными типами операций одной даты сохранён прежний приоритет этапов; точную межтиповую хронологию из этих данных восстановить нельзя.
- Клиентский Excel-бандл порядка 1,28 МБ до gzip остаётся кандидатом для оптимизации.
- Прочие процессы, возвраты/списания/инвентаризация и переход на PostgreSQL не объявляются завершёнными этим аудитом.

Подтверждённых блокирующих дефектов в проверенном объёме не осталось. Результат пригоден для передачи кода разработчику с указанными ограничениями. welding-journal не изменялся.
