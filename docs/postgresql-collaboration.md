# PostgreSQL и совместная работа

Переход выполнен 09.11.2026 по прямому поручению пользователя. Целевой объём: до 50 000 позиций и 5–10 одновременно работающих пользователей. Размещение в интернете пользователь отложил; приложение работает локально на `http://127.0.0.1:43187/`.

## Запуск этого клона

PostgreSQL уже подготовлен, данные перенесены. Для обычного запуска:

```bash
pnpm db:local:start
pnpm dev
```

`db:local:start` запускает/переиспользует только кластер `.materials-workspace/postgres/data` на `127.0.0.1:55432`; чужой процесс на занятом порту не останавливается. PostgreSQL 18 должен быть установлен и доступен в PATH. Основная база — `materials`, тестовая — `materials_test` на том же сервере. Пароль сгенерирован случайно и находится в исключённом из Git `.env` с правами 0600. Остановка только этого кластера: `pnpm db:local:stop`.

Создан администратор `admin`. Его данные входа находятся в `.materials-workspace/access/7bbd8573-5968-4dbe-a7f4-bd430087f08e.txt`; файл не коммитить и не публиковать. После входа кнопка «Пользователи» позволяет добавлять редакторов/администраторов, отключать учётные записи и менять пароли. Отключение или смена пароля отзывает сеансы пользователя. При истечении сеанса кнопка «Войти снова» сохраняет открытые правки вкладки.

## Новый клон или сервер

База и файлы пользователя не передаются с Git. После установки зависимостей и PostgreSQL подготовка выполняется **явно**, один раз:

```bash
pnpm db:local:start
pnpm db:workspace:import
pnpm user:add admin "Администратор" admin
pnpm dev
```

Для существующего PostgreSQL задайте `DATABASE_URL` и отдельный `DATABASE_URL_TEST` в `.env` вместо `db:local:start`. Альтернативный `docker-compose.yml` поднимает PostgreSQL приложения на 55432 и тестовый на 5433; оба порта привязаны к 127.0.0.1. Не запускайте native PostgreSQL и Docker на одном порту.

`db:workspace:import` применяет миграции Drizzle, создаёт резервную копию старого JSON, импортирует данные одной транзакцией и сверяет значения всех записей. При отсутствии JSON создаётся пустая база. Повторный импорт в уже подготовленную базу запрещён. Отдельное применение будущих миграций: `pnpm db:workspace:migrate`. Обычные `pnpm dev`/`pnpm start` не выполняют миграции, seed или сброс.

`pnpm user:add login "Имя" [editor|admin]` генерирует пароль и записывает его в защищённый локальный файл. Можно передать пароль через переменную `MATERIALS_NEW_PASSWORD`; не помещайте секрет в историю команд или Git.

## Что изменилось в сохранении

- `workspace_records` хранит отдельные материалы, строки заявок/поступлений/выдач, ЗНИ со всеми ревизиями, документы АПП/М-15, возвраты и настройки. Payload отдельных документов — JSONB, идентификаторы, версии, порядок и ссылки индексируются отдельно. Это сохраняет действующий формат документов; старые SQL-таблицы заготовки не являются источником данных интерфейса.
- Клиент сравнивает только изменившиеся коллекции, отправляет изменённые записи и их ожидаемые версии. Полное копирование, проверка и запись JSON при каждом сохранении удалены из рабочего пути.
- Проверки учёта выполняются на сервере для связанной части данных. Изменения проходят в одной транзакции; ошибка отменяет весь запрос. Короткая общая транзакционная блокировка PostgreSQL упорядочивает записи и защищает составные инварианты, но общая версия базы больше не блокирует независимые правки устаревших клиентов.
- Версии отдельных записей и групп заявок/выдач предотвращают потерю одновременных правок. Новый документ не присоединяется молча к чужому документу с совпавшим номером.
- `workspace_commits` хранит время, автора, изменения и UUID операции. Повтор с тем же UUID возвращает прежний результат; потерянный ответ не создаёт повторную выдачу/возврат.
- Изменения считываются по курсору журнала каждые две секунды в активной вкладке. Во время ввода, редактирования ячейки и открытого модального окна применение откладывается. Черновик остаётся у пользователя; при сохранении версии проверяются повторно.
- Конфликты показывают «Было / Ваше изменение / Сейчас в базе». Выбор своих значений повторно проходит все серверные проверки; подписанные ЗНИ/АВК, фактические возвраты и остатки сохраняют прежнюю защиту.

Очередь неподтверждённых правок хранится в `materials.pending.v2.<clientId>` в localStorage, отдельно для вкладки и учётной записи. В ней только изменения, а не вся база. Восстановление повторяет незавершённый запрос с тем же UUID и проверяет версии. При недоступном хранилище/квоте интерфейс предупреждает; перед закрытием нужно дождаться подтверждения сервера или скачать копию. Это восстановление правок, а не автономный режим работы без сервера.

## Перенесённые данные и резервные копии

Перенесено и сверено 4 885 записей, включая 4 813 строк материалов, 17 строк заявок, 14 поступлений, 2 выдачи, 3 ЗНИ, 7 документов получения и 1 возврат. Исходный `.materials-workspace/workspace.json` и резервные копии `backups/before-postgres-*.json` оставлены без изменения. Приложение больше не обновляет этот JSON и не импортирует поверх PostgreSQL старый localStorage. Полная замена через прежний RPC отклоняется с предложением сохранить копию и обновить старую вкладку.

Снимок PostgreSQL: `pnpm db:backup` (нужен `pg_dump` совместимой версии). Получается файл `.materials-workspace/backups/materials-*.dump`. Дополнительно сохраняйте `document-files` и `print-templates` из `MATERIALS_WORKSPACE_DIR` (по умолчанию `.materials-workspace`). Для согласованной копии базы с вложениями на общем сервере приостановите изменение документов на время копирования. Не копируйте каталог работающего PostgreSQL как замену `pg_dump`.

Откат после перехода — восстановление проверенной резервной копии в отдельную базу и переключение `DATABASE_URL`. Исходный JSON представляет только состояние на момент переноса и не содержит новых операций. Не заменяйте им действующую базу с новыми изменениями.

## Проверки

09.11.2026 полный прогон с настоящим PostgreSQL: 42 файла, 470 тестов прошли, 4 опциональных теста пропущены. Нагрузка на 50 000 позиций выполнена отдельно и прошла. После уточнения порядка новых строк повторно прошли 42 теста очереди, восстановления и авторизации. TypeScript, ESLint, Prettier и production build прошли. В браузере проверены вход, загрузка перенесённых данных и окно пользователей; ошибок в консоли не было.

Резервная копия `materials-2026-11-09T15-14-58.925Z.dump` восстановлена в отдельную временную тестовую базу: все 4 885 записей совпали с исходным JSON. После проверки удалена только эта временная база. Исходный JSON сохранил контрольную сумму; рабочие записи не заменялись нагрузочными наборами.

```bash
pnpm db:test:prepare
pnpm test:postgres
pnpm exec vitest run src/features/materials/workspace-collaboration.test.ts src/features/materials/workspace-auth.test.ts
pnpm test --maxWorkers=2
pnpm exec tsc --noEmit
pnpm lint
pnpm build
```

PostgreSQL-тесты требуют `MATERIALS_POSTGRES_TEST=1` (скрипт `test:postgres` устанавливает его) и отдельный `DATABASE_URL_TEST` с именем базы, оканчивающимся на `_test`. Они создают случайную собственную схему и удаляют только её. Тестовые записи в основную базу и браузерный localStorage не загружаются.

Нагрузка с полной историей на каждой позиции:

```bash
MATERIALS_POSTGRES_TEST=1 MATERIALS_POSTGRES_SCALE=1 \
MATERIALS_POSTGRES_SCALE_REPORT=/tmp/materials-postgres-scale.json \
NODE_OPTIONS=--max-old-space-size=6144 \
pnpm exec vitest run src/features/materials/workspace-postgres.test.ts --maxWorkers=1
```

Замер 09.11.2026, 50 000 позиций с заявками, поступлениями, подписанными ЗНИ/АВК, выдачами и возвратами: десять независимых одновременных правок — **13–88 мс**, все десять сохранены. Один запрос — **527 байт**. Полное чтение из PostgreSQL — **1 962 мс**, разовый импорт — **17 699 мс**, heap процесса после замера — около **851 МиБ** (не пик). Это локальный серверный тест без HTTP, отрисовки и интернет-задержки. Для сравнения: прежнее сохранение JSON на сопоставимой насыщенной истории занимало около 12 секунд и давало 9 конфликтов из 10 независимых правок.

## Будущее размещение в интернете и границы

Публикация пока не выполнялась. Для неё потребуется общий сервер с PostgreSQL, Node.js 24, pnpm, LibreOffice для PDF и постоянным диском для вложений/шаблонов. Соберите приложение `pnpm build`, запускайте `pnpm start` на 127.0.0.1:43187 за reverse proxy с действующим HTTPS-сертификатом; задайте точный `APP_ORIGIN=https://ваш-домен`. PostgreSQL не публикуйте в интернет.

Вход обязателен для данных, сохранений, файлов и печати. Пароли хэшируются scrypt; сеансы хранятся в PostgreSQL, cookie — HttpOnly/SameSite, с Secure при HTTPS. Запросы изменения проверяют Origin, вход ограничен по частоте. Администрирование пользователей проверяет роль на сервере. Все учётные записи принадлежат одной общей базе; разделение доступа по проектам/организациям не реализовано.

Для текущего объёма предусмотрен **один экземпляр веб-приложения**, обслуживающий всех пользователей. Хотя транзакции PostgreSQL работают между процессами, файловые вложения и шаблоны пока требуют одного общего владельца файлового хранилища; несколько независимых веб-реплик не заявляются как поддерживаемая конфигурация.

Первичная загрузка пока получает весь набор данных, а фильтрация таблиц остаётся клиентской. Большая история на 50 000 позициях требует дальнейшего перехода списков на серверную пагинацию для быстрого холодного открытия через интернет. Текущий замер подтверждает ускорение **сохранения** и корректность конкурирующих операций; он не является замером начальной загрузки страницы на десяти удалённых компьютерах. Ограничения PDF-разбиения и большой клиентский Excel-бандл из предыдущего аудита этим изменением не устранялись.
