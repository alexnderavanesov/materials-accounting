# Materials: основные моменты

Обновлено 26.11.2026 (Europe/Moscow). Это краткая память проекта, а не полная история и не доказательство актуальности прежних проверок.

## Первая загрузка проектной базы по шифру — 26.11.2026

При импорте Excel в шифр без сохранённых позиций и истории первая загрузка создаёт одну запись «Исходный состав» со всеми позициями, датой и автором. После предпросмотра пользователь подтверждает сохранение. В смешанном файле причина и номер ИЗМ относятся только к изменениям существующих шифров. Оба режима импорта поддерживают первую загрузку. У шифра с прежними позициями и без истории исходный состав по-прежнему фиксируется по сохранённым позициям перед первым изменением.

## Масса в предпросмотре импорта проектной базы — 26.11.2026

Пустая масса допустима, заполненная должна быть конечным числом не меньше нуля. При ошибке, включая ошибку формулы Excel, предпросмотр показывает номер позиции и проблемное значение. Счётчики учитывают весь файл. Если есть ошибки, список открывается с фильтром «Только позиции с ошибками», который можно снять. Переход к изменениям доступен после исправления всех ошибок.

## Обязательные оригиналы АПП и один PDF для М-15 — 24.11.2026

- Последнее решение пользователя заменяет прежнюю возможность нескольких файлов М-15: у накладной допускается один PDF до 20 МБ, добавление либо замена. В карточке, окне файлов и разделе «Документы» нет выбора «Оставить несколько» для М-15. API также проверяет количество, расширение и содержимое; замена атомарна по файловому манифесту. Старые вложения автоматически не удаляются, привести прежний набор к одному PDF можно явной заменой.
- В реестре накладных добавлен столбец «Файл М-15» с именем оригинала; отсутствие показано красным «Нет скана». Список обновляется после загрузки/замены и при возвращении в окно. Ошибка чтения показана отдельно, не как отсутствие файла.
- Сохранение получения требует загруженный файл каждого АПП; создание/изменение М-15 — один PDF. Для АПП сохранены несколько оригиналов и прежние поддерживаемые форматы. Последний оригинал АПП и скан М-15 нельзя удалить отдельно, доступна замена.
- Обязательные оригиналы загружаются **до** записи операции по устойчивому ID документа. API принимает проверенные реквизиты черновика и сохраняет исходник в существующем файловом каталоге; при последующем сохранении операции ID не меняется и второй оригинал не создаётся. При отказе сохранения операции загруженный файл остаётся доступен для повтора/в разделе «Документы». Дополнительные паспорта и другие документы получения загружаются после учётной записи. Серверный обработчик изменений рабочего пространства проверяет наличие оригиналов у изменяемых операций; чтение старых неполных записей и несвязанные изменения не блокируются.
- В браузере проверены имена сканов в реестре и действие «Заменить PDF-скан». Рабочие операции и файлы не изменялись. Проверки записи и отказов используют временное файловое хранилище или подменённый API; миграции и сбросы не выполнялись.
- Проверены 101 профильный сценарий документов/М-15 и все 147 сценариев рабочего пространства (146 в общем прогоне, проверка защиты основания ЗНИ повторена после обновления асинхронного ожидания). Покрыты запрет сохранения без оригинала, ошибка загрузки, повтор сохранения без дублей, замена PDF, конфликт вложений, восстановление чтения каталога и сохранность прежнего файла. TypeScript, ESLint, форматирование и production build проходят. Commit/push не выполнялись.

## Иерархия Escape и Enter в фильтрах — 24.11.2026

- Общий `src/components/ui/escape-layer.tsx` управляет клавиатурными слоями через React-контекст, включая порталы. Одно нажатие Escape обрабатывает только верхний слой: список/меню/фильтр или редактирование ячейки; затем сбрасывает активные фильтры открытого окна; затем закрывает само окно. Фильтры фоновой страницы не сбрасываются, пока сверху есть окно. Независимые окна учитывают порядок открытия, вложенные — родительскую связь; удержание клавиши не закрывает несколько уровней.
- Подключены общие формы операций, ЗНИ/АВК, проектных изменений, импорта, сканов и предпросмотра, AppSelect, меню действий/Excel, мобильное меню и AG Grid. Сохранены блокировка закрытия во время сохранения и имеющиеся подтверждения несохранённых данных. Escape в подтверждении удаления файла или отказа от черновика отменяет подтверждение. Закрытие старого меню AG Grid при открытии «Выбрать столбцы» не отключает слой нового окна.
- Второй Escape сбрасывает фильтры и поиск только текущей формы/раздела; обязательные реквизиты (шифр и типы заявки, выбранная заявка получения) остаются. Enter применяет черновик фильтра столбца из поиска, списка значений и элементов перемещения/размера; кнопки «Отмена», «Очистить» и закрытие сохраняют собственное действие Enter.
- В браузере на существующей М-15 проверены Enter, последовательные Escape для фильтра/сброса/формы и отдельное закрытие вложенного скана. Рабочие операции и файлы не сохранялись.
- Проверены все 146 сценариев рабочего пространства: 106 прошли повторным прогоном после исправления меню, оставшиеся 39 — отдельно; прежнее ожидание сохранения режима «Заполненные» обновлено под сброс фильтров и также прошло отдельно. Профильные проверки окон, таблиц и документов прошли (132 в регрессионном наборе, 47 в завершающем наборе, с пересечением). TypeScript, ESLint, форматирование и production build успешны. Commit/push не выполнялись.

## Получения только по АПП, независимые М-15 и чистый старт — 20.11.2026

- Получение требует АПП (номер и дата); полей, создания и распределения М-15 внутри получения больше нет. Новые ЗНИ оформляются только по АПП. Новый Excel-шаблон получения не содержит М-15; при чтении старого шаблона эти колонки игнорируются с пояснением, не блокируя корректные строки АПП.
- М-15 создаётся отдельно: номер, дата, один шифр, состав и сканы. Состав вводится вручную или импортируется из Excel; заполнение по заявке удалено по последнему указанию пользователя. М-15 допускается до получения и сверх количества АПП; связь с отдельными получениями отсутствует. При разных единицах требуется явный коэффициент М-15 → проектная единица. Новые записи имеют `mode: independent`, пустые `allocations`; прежние модели оставлены только для чтения/защиты исторических копий.
- Сверка агрегируется по ID проектной позиции и исходному шифру. АПП = фактическое получение минус возврат заказчику; выдачи, возвраты с участка и переносы остатков не меняют документальные количества. М-15 = сумма её составов в проектной единице. Таблица показывает АПП, М-15, нехватку, превышение и «Состав М-15» с уникальными ссылками. Клик открывает сканы, при их отсутствии — состав. Есть фильтр «Не хватает М-15». Количество по М-15 добавлено в обзор и расшифровку по шифрам.
- Документ определяется типом, нормализованным номером и датой. При выборе «Оставить несколько» каждый выбранный файл добавляется как отдельное вложение со своим ID, в том числе при полном совпадении имени и содержимого. Это правило сохраняется для АПП и прочих документов; М-15 с 24.11.2026 ограничена одним PDF (см. актуальное решение выше). Содержимое по-прежнему хранится один раз по SHA-256. Удаление одного вложения сохраняет оригинал, пока на него ссылается другое. «Заменить» заменяет ранее показанный набор вложений. Повтор запроса с устаревшим списком отклоняется. Ранее пропущенные копии можно добавить повторной загрузкой.
- Пользователь прямо разрешил удалить все операции и их документы, отдельно подтвердил сохранение проектной базы. Выполнена разовая очистка PostgreSQL `pg:105 → pg:106`: удалены 129 записей (заявки, получения, М-15, ЗНИ/АВК, выдачи и возвраты), 6 файлов, сброшены счётчики нумерации. ## Скрепки и повторная загрузка сканов — 20.11.2026

- В форме получения скрепки добавлены у общих и индивидуальных АПП/М-15, а также у АРВК заказчика, документа качества, паспорта/сертификата и технического решения. Серый цвет означает отсутствие загруженных файлов, зелёный — наличие; синий счётчик показывает выбранные, ещё не загруженные файлы. Для привязки сначала заполняются реквизиты документа.
- Окно скрепки показывает прежние файлы с предпросмотром. При повторной загрузке требуется явный выбор «Заменить» или «Оставить несколько». Такой же выбор и предпросмотр есть при загрузке во вкладке «Документы» и в карточке М-15. Замена относится ко всем прежним файлам выбранного документа; вложения других документов не затрагиваются.
- В получении файлы остаются в черновике до сохранения операции. После завершения очереди сохранения они загружаются в существующий реестр: АПП/М-15 по ID документа, дополнительные документы по ID получения и полю. Изменившиеся реквизиты или исключённые строки блокируют неверную привязку. При частичном сбое форма сохраняет оставшиеся файлы для повтора, без повторного создания получения и повторной отправки уже успешных файлов.
- Замена файлов выполняется одной атомарной записью файлового манифеста: прежние оригиналы удаляются только после успешной записи новых. Ревизия манифеста и точный список просмотренных файлов защищают от замены файлов, добавленных параллельно. Изменений схемы БД и миграций нет; рабочий snapshot в проверке не менялся.

- Проверены 236 сценариев: 90 проверок документов/сканов/М-15 и 146 сценариев рабочего пространства с адресными повторами. В общем прогоне обнаружены и исправлены два устаревших ожидания тестов М-15: порядок уже добавленных справочных столбцов и ожидание ленивого открытия карточки. После исправлений проблемные и оставшиеся сценарии прошли. TypeScript, ESLint, форматирование, `git diff --check` и production build успешны. В браузере проверены оба блока скрепок, окно загрузки и Escape без закрытия получения; операции и файлы рабочих данных не сохранялись.

## Общие данные: подсветка и сортировка — 02.11.2026

По просьбе пользователя убраны прежние голубые/жёлтые/красные статусы карточек материалов. Зелёная подсветка означает полное получение проектного количества по всем шифрам материала, независимо от заявленного количества и ВК. Остаток считается отдельно по каждой проектной позиции и затем складывается по единицам: избыток по одному шифру не закрывает недостачу по другому. Учитывается фактический возврат непринятого по ЗНИ; возврат лишнего, как и раньше, не восстанавливает потребность.

На вкладках операций, кроме «Входного контроля», единый ряд из семи показателей: «Получено», «Осталось получить», «Ожидает инспекции», «Ожидает АВК», «Доступно к выдаче», «К возврату», «Возвращено». С 05.11.2026 бейджики показывают число уникальных материалов с положительным показателем, а при наведении или фокусе — количества отдельно по единицам. Несколько поступлений/шифров одного материала не увеличивают счётчик; частично полученный материал может одновременно учитываться в полученных и ожидаемых. «Получено» — суммарное фактическое получение до возвратов. «Осталось получить» — положительные остатки отдельных позиций существующих заявок с учётом фактических возвратов непринятого; это не остаток до проекта. Показатель «Без заявок» убран. Зелёная подсветка полного получения проекта считается отдельно и не меняется от новой трактовки бейджика.

Нажатие поднимает соответствующие материалы/документы, повторное возвращает обычный порядок; другие строки не скрываются, разные единицы не сравниваются. Остальные показатели используют общий `receiptBalances`. В AG Grid сохраняется сортировка по столбцам внутри каждой группы приоритета. Сортировка сохраняется отдельно для вкладки, применяется перед пагинацией и сбрасывает страницу на первую. Пагинация только внизу, включая короткие списки. Рабочие данные при сортировке не сохраняются.

На всех вкладках операций доступны общая строка поиска и отдельные фильтры «Шифр»/«Тип материала» с подсказками. Условия работают совместно; шифр и тип должны совпасть у одной позиции. Найденная заявка или ЗНИ сохраняет полный состав при раскрытии. Текст, шифр, тип и выбранный бейджик сохраняются отдельно для каждой вкладки в sessionStorage; смена условий возвращает первую страницу. Переход к конкретному документу из общих данных очищает скрывающие его фильтры. Поиск включает нормативный документ и состав материала. Рабочий snapshot и бизнес-расчёты не меняются.

В «Возврате» ожидающие возврата позиции идут по дате подписания ЗНИ, все полученные материалы — по дате получения. «Общие данные» учитывают последнюю операцию материала, включая ЗНИ/АВК, выдачи и возвраты; материалы без операций идут ниже по алфавиту.
