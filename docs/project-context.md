## Сохранность данных

Пользователь отдельно сообщил о пропаже данных и некликабельных кнопках после запусков/переноса папки. Это ключевая регрессия, которую нельзя возвращать.

- Рабочий snapshot: `.materials-workspace/workspace.json`, исключён из Git. Также используется ключ `materials.projectWorkspace.v1` в localStorage.
- Главная страница имеет `ssr: false`: это ранее устраняло hydration mismatch между сервером и браузерными данными.
- Loader ждёт snapshot перед монтированием интерфейса. После аудита серверная версия имеет приоритет над устаревшим localStorage; отличающаяся копия сохраняется для восстановления. Pending offline-копия автоматически восстанавливается только при совпадении её базовой серверной ревизии. Обычное открытие страницы не запускает save.
- Смена порта/host меняет origin и localStorage. Использовать постоянный адрес с `127.0.0.1`, не менять его на localhost без необходимости.
- В аудите 14.10.2026 исправлены проглатывание ошибок чтения, безусловная запись при открытии, гонки сохранения и перезапись свежих данных устаревшей вкладкой. Используются проверка версии, атомарная замена файла и очередь. Ошибки/конфликты видны в интерфейсе; доступно скачивание копии и retry временной ошибки. URL-сброс удалён. Подробности и ограничения — в отчёте аудита.
- Не открывать `?reset=1`, не очищать браузерное хранилище, не выполнять seed/reset/миграции ради запуска. Резервную копию и тестовые данные хранить отдельно от рабочего snapshot, вне Git.

## Проверки и незавершённые темы

15.10.2026 добавлена шестерёнка слева над таблицей проектной базы: чекбоксы управляют видимостью всех реквизитов, каждого шифра и «Действий». «Показать все» восстанавливает столбцы; фильтр скрываемого столбца сбрасывается. Выбор хранится отдельно в браузере (`materials.projectMatrix.hiddenColumns.v1`) и не меняет рабочий snapshot, расчёты или экспорт. Новые шифры видны по умолчанию. Даже если скрыты все столбцы, настройки остаются доступны.

Клик по подписи чекбокса переключает его и оставляет список открытым. Закрытие — повторное нажатие на шестерёнку, клик/переход фокуса снаружи или Escape; временный blur при клике по label не закрывает список. Escape в этом списке не сбрасывает фильтры базы.

Карточка проектной базы ограничена доступной шириной экрана: заголовок, поиск, кнопки и шестерёнка не растягиваются вместе с таблицей. Горизонтальная прокрутка находится внутри таблицы; закреплённые крайние столбцы имеют непрозрачный фон.

После обновления страницы восстанавливаются раздел, вкладка операций, состояние бокового меню, поиск/фильтры, раскрытые материалы/документы и прокрутка страницы/таблиц. Навигация хранится отдельно для вкладки браузера в `sessionStorage` с префиксом `materials.workspaceView.v1:`; рабочий JSON и его localStorage-копия этим не меняются. Прокрутка запоминается отдельно для проектной базы и каждой вкладки операций. Несохранённые формы и диалоги не восстанавливаются.

Доработка в клоне основного разработчика 14.10.2026: «Наименование по проекту» при создании и редактировании материала — обязательное свободное текстовое поле. Выбор из ранее введённых наименований не требуется; пустое значение не допускается. Проверки справочников остальных полей и защита от дублирования комбинаций сохранены.

15.10.2026 по просьбе пользователя убран ручной «ID материала» из карточки, таблиц, списков и форм операций. Связи используют внутренний `line.id` / `projectLineId`: при создании вручную, добавлении нового шифра и импорте ID генерируется автоматически (`createClientId('line')`, UUID при наличии Web Crypto), затем сохраняется в workspace. Уже существующие ID и связи не заменяются; редактирование реквизитов их не меняет. Прежнее поле `materialId` сохранено в данных и совместимости Excel, но больше не отображается и не редактируется в интерфейсе. Это отдельный старый код, не внутренний ключ позиции.

15.10.2026 согласовано и реализовано разделение проектного и заявленного количества. «По проекту сейчас» показывает сумму материала по всем шифрам, «По шифру сейчас» — актуальный план выбранного шифра; таблица и форма заявки используют единый расчёт. Изменение проектной базы не меняет `quantity` сохранённых заявок. Остаток учитывает все заявки по позиции, при превышении показывается отдельное предупреждение, в том числе при нулевом проектном количестве. Сохранение примечаний и уменьшение уже заявленного количества допускаются даже при сохраняющемся превышении; новые заявки и увеличение количества требуют устранения нехватки. Явное увеличение проекта из диалога учитывает и превышение других заявок.

Для новых позиций заявки сохраняется `projectQuantitiesAtCreation` (сумма по проекту, количество по шифру и единица). История не меняется при последующих правках проекта или заявки и отображается отдельно от текущих значений. У старых записей без этого поля выводится «не сохранялось»; подставлять текущий план задним числом нельзя. Данные по-прежнему хранятся в JSON workspace, без миграций и записи при простом открытии. Сценарии проверены изолированными UI-тестами: несколько шифров/заявок, уменьшение и обнуление плана, сохранение истории, редактирование старых заявок и явная корректировка превышения. Итог проверки 15.10.2026: 59 тестов в пяти файлах, TypeScript, ESLint, форматирование и сборка прошли; проверка списка заявок в браузере не изменила рабочий snapshot.

Пересчёт единиц (14.10.2026, выполнено): в карточке материала задаются необязательные `alternativeUnit` и `alternativeUnitFactor` — количество альтернативных единиц на одну основную. Пользователь подтвердил правило: 1 шт = 2 кг → заявка на 3 шт = 6 кг. Альтернативная единица вводится с подсказками из `configuredUnits`, коэффициент должен быть конечным положительным числом. Масса единицы остаётся отдельным реквизитом и не используется как неявный коэффициент. Данные сохраняются в текущем JSON workspace; PostgreSQL и миграции не затрагиваются.

По уточнению пользователя прежние заявки тоже пересчитываются автоматически по текущим `alternativeUnit` и `alternativeUnitFactor` материала. Это касается записей со старым коэффициентом, с `null` и без поля `altUnitFactor`. Пересчёт применяется ко всем связанным заявкам при загрузке и изменении материала; таблицы, формы и сохраняемый snapshot получают одинаковые значения. Открывать и пересохранять каждую заявку не нужно. Обычное открытие страницы по-прежнему не отправляет save; при следующем изменении пересчитанные данные сохраняются вместе с остальным workspace.

15.10.2026 пересчёт распространён на получение и выдачу, включая сохранённые операции. В заявках, получении и выдаче нет ручных полей альтернативного количества/единицы, в том числе у старых записей: показаны только результат и коэффициент. Единственный источник настройки — карточка материала в проектной базе. Каждая операция умножает собственное количество в основной единице на коэффициент; сумма получений разделена по альтернативным единицам. Во входном контроле ручных альтернативных полей нет.

Текущий коэффициент применяется только при совпадении основной единицы материала и документа. Если материал удалён или настройка недоступна, используется последний сохранённый коэффициент этой операции (для нового получения — заявки, для новой выдачи — получения). У старых записей без коэффициента значения остаются справочными: можно менять реквизиты, но изменение количества требует настройки пересчёта в базе. Коэффициент из старых количеств не угадывается. Новые операции без настройки сохраняются без альтернативных значений; наличие пересчёта необязательно. Открытие приложения не отправляет save; пересчитанные записи входят в следующий пользовательский save.

Excel-шаблоны заявок и получения содержат защищённые формулы и справочную альтернативную единицу; вводить их не нужно. При импорте альтернативные колонки не являются входными данными: приложение вычисляет значения по текущему коэффициенту, даже если файл содержит устаревший результат. Пустые строки шаблона игнорируются. Импорт/экспорт проектной базы по-прежнему переносит единицу и коэффициент. PostgreSQL и миграции не затрагиваются.
