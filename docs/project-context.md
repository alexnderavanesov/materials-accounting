## Сохранность данных

Пользователь отдельно сообщил о пропаже данных и некликабельных кнопках после запусков/переноса папки. Это ключевая регрессия, которую нельзя возвращать.

- Рабочий snapshot: `.materials-workspace/workspace.json`, исключён из Git. Также используется ключ `materials.projectWorkspace.v1` в localStorage.
- Главная страница имеет `ssr: false`: это ранее устраняло hydration mismatch между сервером и браузерными данными.
- Loader ждёт snapshot перед монтированием интерфейса. После аудита серверная версия имеет приоритет над устаревшим localStorage; отличающаяся копия сохраняется для восстановления. Pending offline-копия автоматически восстанавливается только при совпадении её базовой серверной ревизии. Обычное открытие страницы не запускает save.
- Смена порта/host меняет origin и localStorage. Использовать постоянный адрес с `127.0.0.1`, не менять его на localhost без необходимости.
- В аудите 14.10.2026 исправлены проглатывание ошибок чтения, безусловная запись при открытии, гонки сохранения и перезапись свежих данных устаревшей вкладкой. Используются проверка версии, атомарная замена файла и очередь. Ошибки/конфликты видны в интерфейсе; доступно скачивание копии и retry временной ошибки. URL-сброс удалён. Подробности и ограничения — в отчёте аудита.
- Не открывать `?reset=1`, не очищать браузерное хранилище, не выполнять seed/reset/миграции ради запуска. Резервную копию и тестовые данные хранить отдельно от рабочего snapshot, вне Git.
- Docker Compose описывает материалы на 55432 и тестовую БД на 5433. Главный рабочий интерфейс сейчас читает snapshot; наличие Drizzle/PostgreSQL не означает, что все процессы уже переведены на БД. Миграции/изменение БД — только по отдельному разрешению.

## Проверки и незавершённые темы

20.10.2026 в предпросмотре Excel-получения включено редактирование количества, даты и всех реквизитов поступления двойным нажатием на ячейку. Служебные поля остаются серыми и readonly; альтернативы вычисляются общей логикой. После каждой правки повторяется проверка строки и всего черновика, включая запрет повторных заполненных позиций заявки. Enter/Tab/уход фокуса подтверждают ввод, Escape отменяет только текущую правку. Применение фиксирует активный редактор и повторно валидирует данные; до кнопки «Сохранить получение» записи workspace не меняются. Кнопки скачивания шаблона и загрузки всегда видны; «Загрузить исправленный файл» заменяет весь черновик, в том числе правки в таблице, и допускает повторный выбор того же имени. Ошибка чтения блокирует применение старого файла, запоздалое завершение предыдущей загрузки не перезаписывает новую. Общий OperationsGrid допускает редактирование только явно указанных столбцов черновика; остальные учётные таблицы сохраняют прежний режим.

20.10.2026 исправлены даты в Excel-получении: колонка «Дата поступления» заполняется датой из формы/редактируемого поступления либо текущим локальным днём, хранится как дата Excel с форматом `dd.mm.yyyy` и доступна для правки. Импорт переводит числовые даты Excel (с учётом системы 1900/1904), текст ДД.ММ.ГГГГ и ISO в ГГГГ-ММ-ДД. Некорректная введённая дата блокирует применение с объяснением; пустая дата старого шаблона использует дату формы или сегодняшний день. Дата видна в предпросмотре, строки с одной предзаполненной датой и без количества по-прежнему пропускаются. Изолированные проверки покрывают шаблон, разные форматы/календарные ошибки, сохранение и повторное открытие получения; исторические рабочие записи не переписываются.

Уже оформленные поступления сохраняются историческими карточками, в том числе при частичном получении заявки. Подтверждение удаления теперь заранее объясняет результат и показывает количество связанных поступлений. Связь определяется ID позиции заявки, а не совпадением материала. Проверяется исчезновение пустых карточек и сохранение фактических поступлений после удаления и перезагрузки. Рабочие записи автоматически не очищаются.

Если материал удалён или настройка недоступна, используется последний сохранённый коэффициент этой операции (для нового получения — заявки, для новой выдачи — получения). У старых записей без коэффициента значения остаются справочными: можно менять реквизиты, но изменение количества требует настройки пересчёта в базе. Коэффициент из старых количеств не угадывается. Новые операции без настройки сохраняются без альтернативных значений; наличие пересчёта необязательно. Открытие приложения не отправляет save; пересчитанные записи входят в следующий пользовательский save.

Excel-шаблоны заявок и получения содержат защищённые формулы и справочную альтернативную единицу; вводить их не нужно. При импорте альтернативные колонки не являются входными данными: приложение вычисляет значения по текущему коэффициенту, даже если файл содержит устаревший результат. Пустые строки шаблона игнорируются. Импорт/экспорт проектной базы по-прежнему переносит единицу и коэффициент. PostgreSQL и миграции не затрагиваются.
