# Материалы

Локальное приложение для учёта материалов заказчика: проектная база → заявка → фактическое получение → входной контроль → выдача в работу. Возвраты, списания и инвентаризация входят в общий план; наличие серверных заготовок не означает, что эти процессы полностью реализованы.

## Начало работы разработчика

Проверенное окружение: Node.js 24 и pnpm 10.30.3 (закреплён в `packageManager`). Репозиторий: [materials-accounting](https://github.com/alexnderavanesov/materials-accounting).

```bash
git clone https://github.com/alexnderavanesov/materials-accounting.git
cd materials-accounting
pnpm install --frozen-lockfile
pnpm dev
```

Постоянный адрес: **http://127.0.0.1:43187/**. `pnpm dev:open` также открывает браузер. `dev`, `dev:open`, `preview` и `start` используют `strictPort`: при занятом 43187 запуск завершается ошибкой. Не использовать для materials порты 3000 и 3001 и не останавливать чужие процессы.

Рабочая папка владельца — `/Users/alexandravanesov/Documents/Codex/materials`. На другом компьютере используйте свою папку клона; абсолютные пути в документах передачи описывают окружение владельца. Старый путь владельца `/Users/alexandravanesov/Documents/materials` не восстанавливать.

Прочитайте [AGENTS.md](AGENTS.md), [основные моменты](docs/project-context.md) и [пользовательские команды](docs/codex-commands.md). По актуальной договорённости основной разработчик работает в `main`; отдельные ветки и Pull Request — по отдельному запросу. Не включайте рабочие данные и секреты в Git.

## Хранение данных

Текущий рабочий интерфейс сохраняет данные в `.materials-workspace/workspace.json`; браузерная копия — резерв для восстановления. Папка данных исключена из Git. У нового разработчика будет пустая база: рабочие записи владельца не передаются с клоном.

- Snapshot загружается до открытия интерфейса. Ошибка чтения/формата останавливает загрузку, не заменяя файл пустыми данными.
- Изменения сохраняются атомарно и последовательно. Устаревшая вкладка не может молча перезаписать новую серверную версию.
- При конфликте/ошибке интерфейс предлагает скачать текущую копию; при временной ошибке можно повторить сохранение. Отличающиеся браузерные копии сохраняются отдельно для восстановления.
- Используйте одинаковый host `127.0.0.1`: `localhost` имеет другой браузерный origin.
- Не очищайте localStorage/snapshot, не открывайте `?reset=1` и не подменяйте рабочие данные тестовыми. Поддержка reset-параметра удалена.
- `MATERIALS_WORKSPACE_DIR` задаёт отдельную папку snapshot для изолированных тестов. Не указывайте рабочую папку при проверках, меняющих данные.

Это приложение для локального запуска. Snapshot и очередь записи рассчитаны на один процесс сервера; это не многопользовательская БД и не готовая схема удалённого развёртывания. Авторизация для публичного хостинга — отдельная задача.

## Таблицы AG Grid

Проектная база переведена на AG Grid Enterprise **35.2.1**. Версии трёх пакетов закреплены: предоставленная лицензия подходит для релизов до 4 мая 2026 года. Не обновляйте их до более позднего релиза без проверки лицензии.

Локально укажите `VITE_AG_GRID_LICENSE_KEY` в `.env.local` и перезапустите `pnpm dev`. Файл исключён из Git; значение не добавлять в README или исходники. Ключ требуется также при сборке на другом компьютере. Это клиентская лицензия: Vite включает её в браузерный бандл.

- Количества по шифрам редактируются двойным щелчком или клавишей Enter. Enter / Tab / переход к другому полю подтверждает ввод, Escape отменяет. Допустимы дроби с запятой или точкой; пустое поле означает ноль. Ошибочное значение не сохраняется.
- Вставка диапазона из Excel меняет только количества существующих строк. Если одно из вставляемых количеств некорректно или диапазон выходит за строки материалов, вся вставка отменяется. Новые материалы добавляются существующей формой или импортом.
- Заголовки позволяют сортировать, менять ширину, порядок и закрепление. Панели «Столбцы» и «Фильтры» находятся справа. Прежняя шестерёнка управления столбцами работает синхронно с панелью.
- Видимость хранится в прежнем ключе localStorage; порядок, ширина, закрепление, сортировка, фильтры и прокрутка — в sessionStorage текущей вкладки и восстанавливаются при обновлении. Настройки таблицы не меняют рабочий snapshot.
- Кнопка «Excel» непосредственно над таблицей экспортирует видимые столбцы и отфильтрованные строки с числовыми количествами. Верхнее меню Excel для импорта и полного экспорта базы сохраняется.

Реквизиты материала и альтернативный коэффициент редактируются через карточку. Сохранение количеств проходит через существующую очередь workspace с проверкой ревизии; AG Grid не записывает данные самостоятельно. Таблицы «Общих данных», заявок, получений, ВК и выдачи, материалы ЗНИ/АВК и история ревизий, а также проверки импорта заявок/получений используют общий AG Grid. Карточки документов раскрываются по-прежнему. Внутри доступны сортировка, фильтры, выбор столбцов, закрепление, изменение ширины, копирование и экспорт Excel. Раскладка каждой таблицы сохраняется отдельно в sessionStorage. Редактирование и удаление выполняются прежними кнопками и формами, автоматический пересчёт единиц сохранён. Печать формирует весь документ независимо от фильтра таблицы.

Сетка привязок Excel-шаблона в настройках печати остаётся макетом бланка с объединёнными ячейками.

## Печать заявок

В **Проектной базе → Настройка → Шаблоны печати** доступен общий Excel-бланк заявки на получение. Готовый образец работает сразу. Скачайте его, измените оформление и постоянный текст в Excel, загрузите `.xlsx` обратно, проверьте привязки ячеек и предпросмотр, затем нажмите **«Сохранить шаблон»**. Изменения до сохранения являются черновиком. «Отменить изменения» загружает сохранённую версию.

Встроенный бланк повторяет предоставленную форму ООО «Югмонтажстрой»: организация, проект и договор сверху, парные колонки единиц и количеств, шифр проекта в каждой позиции, пять блоков подписей снизу. Номер и дата подставляются одной строкой; наименование, нормативный документ и состав объединяются в одной колонке. Заявитель берётся из заявки, остальные постоянные реквизиты и подписи редактируются в Excel. Номер партии остаётся пустым: в заявке эти данные ещё не определены. Ранее сохранённые пользовательские шаблоны сохраняют свои настройки и оформление.

Поддерживаются один видимый лист (до 200 строк и 40 столбцов), одна строка образца для материалов, обычное оформление, объединённые ячейки и вставленные PNG/JPEG без обрезки или поворота. Размер файла — до 5 МБ. Формулы, макросы, внешние ссылки и сложные объекты отклоняются. Реквизиты связываются с адресами ячеек; для материалов задаются буквы столбцов и номер повторяемой строки. Объединение строки материала с соседними строками не допускается. Область печати должна включать таблицу и подписи. У пустой привязки отключается подстановка данных; чтобы удалить заголовок или столбец, измените сам Excel-бланк.

Кнопка **«Печать»** рядом с заявкой формирует PDF всего документа (до 2000 позиций), независимо от фильтров таблицы. Количества берутся из сохранённой заявки; альтернативные значения пересчитываются по тем же правилам, что в приложении. Просмотр страниц встроен в приложение; PDF можно скачать или открыть отдельно для печати. Документ формируется заново при каждом нажатии, архив печатных версий не ведётся.

Для конвертации нужен **LibreOffice** на компьютере, где запущен сервер приложения. На macOS автоматически проверяется `/Applications/LibreOffice.app`, затем `soffice` в `PATH`. Для другого расположения задайте переменную **в окружении запуска**, например:

```bash
MATERIALS_SOFFICE_PATH=/path/to/soffice pnpm dev
```

Для готовой сборки эта же переменная задаётся перед `pnpm start`. Путь должен вести к исполняемому файлу, без аргументов. На машине конвертера должны быть установлены шрифты, используемые в бланке. Без LibreOffice учёт материалов работает, а печать сообщает о недоступности конвертера.

Файл и привязки сохраняются атомарно в `print-templates/request.json` внутри `MATERIALS_WORKSPACE_DIR` (по умолчанию `.materials-workspace`). Для переноса пользовательского шаблона переносите эту папку вместе с рабочими данными. Печать и предпросмотр не изменяют `workspace.json`; временные файлы конвертера удаляются. Одновременно обрабатывается одна конвертация, тайм-аут — 45 секунд.

Автоматические тесты используют временные папки. Реальную конвертацию и разбиение страниц можно дополнительно проверить командой `MATERIALS_TEST_PDF=1 pnpm test`: нужны LibreOffice и Python с `pypdf`; путь к Python можно задать в `MATERIALS_PDF_PYTHON`. Без этой переменной интеграционная проверка PDF явно отмечается как skipped.

## АПП, ЗНИ и АВК

1. Во вкладке **«Получение»** оформите поступления. Если нужно зарегистрировать акт заказчика, нажмите **«Оформить АПП»**, укажите номер и дату, выберите относящиеся к нему получения и добавьте документы качества. АПП необязателен для ЗНИ.
2. Во **«Входном контроле»** нажмите **«Создать ЗНИ»**. Выберите отдельные полученные материалы и количество либо воспользуйтесь **«Выбрать весь АПП»**. Допустимы несколько материалов, шифров и поступлений; партии и заводские номера остаются отдельными позициями. Количество, включённое в другие ЗНИ, недоступно для повторного выбора. Если часть АПП уже занята, оставшиеся позиции можно выбрать вручную. Заполните дату/время инспекции, участников и результат каждой позиции: принято, принято с замечаниями или не принято. При частичной приёмке укажите принятое количество и замечания.
3. Создайте АВК, заполните комиссию в реквизитах ЗНИ, документы качества, поставщика/изготовителя, десять проверок и заключение. Результаты материалов повторно вводить не нужно. Черновик АВК можно подготовить заранее; подписать его можно после подписания ЗНИ той же ревизии. Фактические даты подписания задаются отдельно от дат документов.
4. В монтаж доступна сумма принятых количеств по действующим подписанным АВК за вычетом выдач. **«Повторная проверка»** создаёт новую рабочую ревизию тех же документов с тем же составом и предъявленным количеством. До подписания нового АВК действует предыдущий; снизить общий допуск ниже уже выданного нельзя. История и печать каждой ревизии доступны в карточке ЗНИ.

Реквизиты новых документов и отдельные шаблоны ЗНИ/АВК находятся в **«Проектная база → Настройка → ЗНИ и АВК · Реквизиты и шаблоны»**. Образцы подготовлены из предоставленных Excel-бланков: у ЗНИ один печатный лист без таблицы материалов, у АВК независимо расширяются таблицы документов качества и материалов. Новая ЗНИ содержит в описании выбранные материалы, количество и сведения о партии. Номер и дата АПП подставляются при наличии; без АПП эти поля пустые. Документы качества копируются из поступлений и АПП в ЗНИ, затем в черновик АВК; их можно уточнить в форме. В таблице АВК печатается предъявленное количество, а частичная приёмка раскрывается в заключении по каждой позиции. Подписи ставятся на документе вручную; приложение сохраняет статус и дату подписания.

Скачивание, загрузка, привязки ячеек, предпросмотр и сохранение шаблонов работают так же, как для заявок. Одно поле можно привязать к нескольким ячейкам, например к ФИО в начале и в конце бланка. Пользовательские шаблоны сохраняются отдельно в `print-templates/zni.json` и `print-templates/avk.json`. PDF использует сохранённую ревизию документа и текущий шаблон; альтернативные количества рассчитывает общая функция приложения. Предпросмотр использует только примерные данные. Для конвертации нужен LibreOffice, как описано выше.

АПП, ЗНИ, АВК и история хранятся в необязательном разделе `qualityWorkflow` рабочего snapshot. Старые записи входного контроля продолжают учитываться и отображаться; они не преобразуются автоматически. Получения с прежним ВК нельзя одновременно включать в новые ЗНИ. Ранее созданные ЗНИ сохраняют историческую привязку ко всему АПП; новые хранят выбранные поступления и копии реквизитов источника. Подписанные документы, их историю и связанные партии нельзя удалить или переписать. Чтение старого snapshot не добавляет новый раздел и не вызывает сохранение.

Проверка реальных PDF ЗНИ/АВК на изолированных данных: `MATERIALS_QUALITY_PDF_QA=/tmp/materials-quality-pdf pnpm exec vitest run src/features/materials/quality-print.test.ts`. Нужен LibreOffice; результаты сохраняются в указанную тестовую папку. Рабочий snapshot не используется.

## База данных

В проекте есть PostgreSQL 18, Drizzle и Docker Compose:

- `postgres`: `127.0.0.1:55432`, база `materials`;
- `postgres-test`: `127.0.0.1:5433`, база `materials_test`.

Обычный запуск текущего интерфейса не требует PostgreSQL, миграций или seed. Подготовка/изменение БД выполняется отдельной задачей с прямым разрешением владельца. `.env.example` содержит пример локальной конфигурации; реальные секреты не коммитить. Интеграционный тест запускается только с `DATABASE_URL_TEST`, указывающим на подготовленную изолированную тестовую БД. Без переменной он отмечается как skipped, а не passed.

## Проверки и сборка

```bash
pnpm exec tsc --noEmit
pnpm test
pnpm lint
pnpm check
pnpm build
pnpm start
```

`pnpm start` и `pnpm preview` показывают сборку из `.output/` через Vite/Nitro на том же порту 43187; сначала остановите свой dev-сервер. Запускайте команды из корня клона, чтобы использовать правильную папку данных. Сборка и preview сами по себе не означают deploy.

Тесты сохранения работают с временными файлами и хранилищем в памяти; UI-регрессии используют jsdom и подменённые серверные функции. Рабочий snapshot в тесты не включается. `pnpm format` изменяет файлы; для проверки используйте `pnpm check`.

Стек: TanStack Start/Query/Router, TypeScript, React, Tailwind, локальные UI-компоненты, PostgreSQL 18/Drizzle, Vitest. Перед соответствующими изменениями TanStack выполняйте guidance-команды из AGENTS.md.
